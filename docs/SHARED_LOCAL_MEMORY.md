## Current implementation

The executable `ComputeUnitWorkgroupScheduler` reference now owns the finite shared/local-memory pool as part of workgroup admission and wave wait lifecycle. A standalone SystemVerilog component implements the same workgroup-scoped byte pool and wave32 32-bit loads and stores. The RTL component is parameterized; its default 32-bank organization is a model choice and is not a frozen architecture requirement.

The C++ reference reserves a real contiguous region transactionally with pooled VGPR state, reports shared-memory fragmentation separately, blocks the affected wave on tagged memory dependencies, and drains terminal requests before resource release. The RTL workgroup frontend allocates and scrubs a region before VGPR activation, rolls it back after a later VGPR reservation failure, and releases it at final whole-workgroup quiescent retirement. Its `cgx1_compute_workgroup_lsu` accepts decoded wave32 memory requests, routes local accesses through that owned region, and exposes an abstract tagged global request/response boundary. Global request lanes preserve the complete 57-bit GPU virtual address for a later translation boundary. Local request lanes use zero-extended 32-bit offsets into the admitted region; nonzero high bits fault instead of aliasing a valid low offset. Multiple waves may wait independently; a waiting wave remains resident, load destinations enter the vector dependency scoreboard, and unrelated runnable waves continue. The LSU captures all request identity, addresses, masks, and store words at acceptance. A wave with a detected terminal memory fault becomes non-issuable while fault delivery is backpressured. An unpresented global request can be dropped on kill; after `valid` has been presented under backpressure, the request stays stable through handshake and the killed wave remains allocated until the matching response drains.

## Reference contract

- A workgroup receives a private contiguous region from the CU byte pool. Allocation uses a four-byte-aligned first-fit base; an allocation can report fragmentation when enough bytes are free in aggregate but no contiguous range fits.
- Region storage is initialized before it is made available to the workgroup. Reused regions cannot expose another workgroup's old data.
- Requests carry workgroup ID, wave ID, caller transaction tag, a 32-bit active-lane mask, 32 byte offsets, and 32 store words. Inactive lanes do not access memory.
- The implemented operation is a naturally aligned 32-bit load or store. The entire active-lane request is checked before any lane is serviced. A misaligned or out-of-range active lane produces a tagged fault completion without partial stores.
- Physical dword bank selection is `(region base + byte offset) / 4 modulo bank count`. Each bank services at most one lane per cycle. Colliding lanes take later cycles; distinct banks can work in parallel. Per-bank arbitration rotates among outstanding transactions.
- One wave can own one outstanding transaction. It remains waiting until its tagged response is consumed. Loads return one word per active lane; stores return an acknowledgement.
- Cancellation suppresses the response but drains already accepted lane service. Accepted stores are not rolled back. Region release waits until service drains and any response is consumed or cancelled.
- Reset drops allocation, request, response, and wait ownership. RTL valid metadata is reset; a newly allocated region is scrubbed before activation.

## Validation and open work

`cgx1_shared_local_memory_checks` covers region capacity, fragmentation, isolation, reuse, wave waits, response tags, mask behavior, fault atomicity, bank conflicts, fairness, cancellation, reset, and seeded randomized service. Workgroup-scheduler tests additionally cover transactional memory-region admission, rejection rollback, memory-wait issue gating, barrier interaction, sibling/workgroup progress, terminal drain, reset, and 5,000 deterministic mixed memory/barrier cycles. The standalone LSU RTL test covers captured local/global requests, local bounds/alignment faults, multiple independent waiters, ready/valid stability, destination writeback backpressure, store acknowledgement, terminal global faults, kill before and after service, reset epoch changes, stale response rejection after slot reuse, and seeded request/fault/reuse sequences. The integrated workgroup frontend test covers shared-region reuse, same-wave instruction ordering, load dependency stalls, sibling progress, a barrier held by a surviving memory waiter, abort quiescence, and automatic fault retirement. The standalone shared-memory RTL test continues to cover its bank service, response stability, cancellation, reset, and allocator behavior.

The first integrated LSU boundary starts after decode because the current ISA table defines a Memory class but no memory opcode or operand encoding; this slice does not invent one. Scalar LSU operations, subword accesses, cache hierarchy, address translation/MMU, atomics, fences, ordering scopes, hardware queue/runtime dispatch, and compiler integration remain open. The global interface is only a decoupled transaction contract and does not perform translation. Bank count and service timing remain parameters. Local model and RTL simulation do not establish synthesis, memory-macro selection, timing, area, power, physical implementation, or silicon behavior.
